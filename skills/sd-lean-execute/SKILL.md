# Execute Lean Feature

Taskmaster is a mirror, not a driver. This skill does not reimplement execution: it runs tlc-spec-lean's Build and Verify exactly as documented in `references/build.md` and `references/verify.md`, and layers one thing on top: syncing status to taskmaster as each slice closes.

Lean has no task list and no batch workers, so the unit of sync is the slice (a taskmaster task) and its checks (subtasks whose title starts with `C<n>`). The order inside the build stays the builder's.

**Everything lands before the proofs.** `check_proofs.py` fails on uncommitted changes outside `.specs/`, and `validate_verification.py` fails when `proofs.md` was written at another `HEAD`. `.taskmaster/tasks/tasks.json` and `docs/` are both outside `.specs/`, so each sync and docs change is committed before `check_proofs.py` runs, never after its last run.

## Steps

Add the following steps as tasks using the `TaskCreate`, `TaskUpdate`, `TaskGet`, and `TaskList` tools. Update the status as you progress through each step to keep the user informed.

| #   | Step                     | Action                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Output / Gate                                                                                                                                                                  |
| --- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Validate tag             | Confirm `.specs/features/{TAG}/checks.md` exists, `validate_checks.py {TAG}` exits 0, and a matching tag exists in `.taskmaster/tasks/tasks.json`                                                                                                                                                                                                                                                                                                                                | Missing or red checks -> report, stop: run `sd-lean-planning` first. Missing taskmaster tag -> tell user to run `sd-insert-taskmaster`, or proceed without sync if they prefer |
| 2   | Read lean skill          | Invoke `/tlc-spec-lean`; read its `references/build.md` and `references/verify.md` once, `references/verify-screens.md` when a criterion cites a capture, and `references/memory.md` when resuming                                                                                                                                                                                                                                                                               | Build and Verify conventions loaded. Resolve these from the skill's own directory                                                                                              |
| 3   | Build slice by slice     | Run Build as documented: tests from the checks, code, commits, the walk and saved pictures. Stop at its "Then stop" section, before `check_proofs.py`                                                                                                                                                                                                                                                                                                                            | Slices implemented, proofs green                                                                                                                                               |
| 4   | Sync each closed slice   | When a slice's proofs are green, before its commit, set each of its check subtasks to `done`, then the slice task. Pass `tag` and `projectRoot`, one id per call. Commit `tasks.json` with the slice when the repo tracks it. A check appended mid-build gets `add_subtask` on its slice first                                                                                                                                                                                   | Taskmaster reflects real progress incrementally, not batched at the very end                                                                                                   |
| 5   | Sync docs                | Invoke `generate-docs` skill in **update mode**, scoped to the commits of this run, if the changes warrant a docs update, and commit the result                                                                                                                                                                                                                                                                                                                                  | `docs/` reflects the feature before the proofs run -- skip silently if no doc-worthy changes occurred                                                                          |
| 6   | UI regression gate       | If the build touched a UI component or screen, test it with Playwright MCP (or similar E2E tool), looking at screens the feature did not set out to change. Lean's walk, pictures and screens sub-agent already judge the screens it changed                                                                                                                                                                                                                                     | No regression in other features -- skip silently for non-UI work. Something broken is fixed and committed before step 7                                                        |
| 7   | Verify                   | Run `check_proofs.py {TAG}`, then dispatch the Verifier and the screens sub-agent as `references/build.md` "Then stop" says, unchanged                                                                                                                                                                                                                                                                                                                                           | Findings in `verification.md`, verdicts in `screens.md`                                                                                                                        |
| 8   | Sync on Verifier outcome | No findings -> statuses stay. Each finding: set the affected check subtask and its slice back to `pending`, or `deferred` if the user chooses not to fix now. A missing obligation is an appended check plus `add_subtask`. Fix everything in one pass, re-sync to `done`, and commit `tasks.json` and any docs change with the fix, then run `check_proofs.py {TAG} --mutations <mutations.json>` and, when the fix changed code, screens round 2 as `references/build.md` says | Taskmaster reflects the fix round, and nothing outside `.specs/` is left uncommitted                                                                                           |
| 9   | Gate                     | Run `validate_verification.py {TAG}`                                                                                                                                                                                                                                                                                                                                                                                                                                             | Exit 0. A red gate is reported first, never left for the reader to find                                                                                                        |
| 10  | Summary                  | Open with the last line of `validate_verification.py`, then what tlc-spec-lean reported, taskmaster sync confirmation (ids updated) and docs sync outcome                                                                                                                                                                                                                                                                                                                        | Local commits are made; `git push` and deploy wait for the user's explicit go-ahead                                                                                            |
| 11  | Save permanent memory    | At the end of the session, evaluate whether there is anything worth saving as permanent memory. Save only what the next session will need and cannot rediscover by reading the code, Git, or CLAUDE.md -- such as the _reason_ behind a decision, a non-obvious invariant, or a user preference; if it is already in the repo or only matters for this specific conversation, do not save it. Use the `ai-memory-durable-pages` skill to persist it.                             | Durable page written when warranted, or nothing when not                                                                                                                       |

## Status mapping

| Outcome                              | `set_task_status` value        |
| ------------------------------------ | ------------------------------ |
| Check's proof green, slice committed | `done`                         |
| Verifier found a gap, fix pending    | `pending` (revert from `done`) |
| User chose not to fix / deferred     | `deferred`                     |
| Slice skipped by user decision       | `cancelled`                    |
| Slice blocked on external dependency | `blocked`                      |

Ids: slice `S2` is task `2`; find a check's subtask by its `C<n>` title prefix and call it as `<slice>.<subtask>`, e.g. `2.3`. The subtask number is the position inside the slice, not the check number.
